# Юзербот-рассыльщик для пользователей

Инструмент из двух связанных частей:

- **userbot.py** — работает под личным Telegram-аккаунтом каждого пользователя панели (через Telethon) и отправляет сообщения его пользователям в личку.
- **bot.py** — обычный Telegram-бот (создаётся через @BotFather), через который каждый пользователь управляет своим аккаунтом: пользователи, шаблоны сообщений, разовая рассылка, расписания, логи.

Всё завязано на общую SQLite-базу (`broadcast.db`), но данные изолированы по пользователям панели: каждый видит только свои шаблоны, пользователей, расписания, логи и настройки.

## 1. Установка

```bash
python3 -m venv venv
source venv/bin/activate   # на Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Получение доступов

1. **API_ID и API_HASH** — зайди на https://my.telegram.org, раздел «API development tools», создай приложение.
2. **BOT_TOKEN** — напиши @BotFather в Telegram, команда `/newbot`, следуй инструкциям.
3. **Свой Telegram ID** — напиши боту @userinfobot, он покажет твой ID.

## 3. Настройка

Все настройки (включая секреты) задаются прямо в `config.py` — отдельный `.env`-файл больше не нужен.

Открой `config.py` и заполни:

```python
API_ID = 1234567
API_HASH = "abcdef1234567890abcdef1234567890"
BOT_TOKEN = "123456:AAExampleTokenFromBotFather"
ADMIN_IDS = [111111111]
```

`ADMIN_IDS` — root-админы панели. Они могут входить сразу и выдавать доступ другим людям через **🛡 Админ-панель** по `@username`. Без `ADMIN_IDS` управляющий бот никого не пустит.

⚠️ `config.py` содержит секреты — не публикуй его и не коммить в открытый репозиторий.

## 4. Первый запуск

```bash
python main.py
```

Юзербот больше не запрашивает код в консоли и не хранит номер телефона в `config.py`. Приложение стартует сразу, а авторизация каждого юзербот-аккаунта выполняется через самого управляющего бота:

1. Напиши управляющему боту `/start`.
2. Если ты root-админ из `ADMIN_IDS`, при необходимости открой **🛡 Админ-панель** и выдай доступ другим людям по `@username`.
3. Каждый пользователь, которому выдали доступ, пишет боту `/start`; бот автоматически привязывает его Telegram ID к выданному username.
4. Выбери **🔐 Авторизация юзербота**.
5. Выбери способ входа:
   - **📱 По номеру телефона** — введи номер, затем код из Telegram, и (если включена 2FA) облачный пароль.
   - **🔳 По QR-коду** — бот пришлёт QR-картинку; отсканируй её в приложении Telegram на аккаунте-юзерботе: *Настройки → Устройства → Подключить устройство*. Код действует ~30 секунд и обновляется автоматически, пока не отсканируешь.

Для настоящих inline-кнопок под постом включи inline mode у управляющего бота в `@BotFather`: команда `/setinline` → выбери бота → задай placeholder. После этого userbot сможет отправлять совместимые посты как `via @bot` с реальной кнопкой под сообщением.

После успешного входа создастся отдельный файл сессии в `sessions/`. У первого root-админа используется старое имя `sessions/userbot.session`, у остальных пользователей — отдельные сессии вида `sessions/userbot_<telegram_id>.session`.

## 5. Как пользоваться

- **Пользователи** → добавь вручную (`username, Имя`), добавь **списком** — просто отправь сообщение или `.txt`-файл со списком username'ов/ID (через пробел, запятую или каждый на новой строке; опционально с именем через запятую), импортируй CSV-файл (`username,full_name` или `telegram_id,full_name`), импортируй участников прямо из группы, где состоит юзербот, удаляй пользователей из списка кнопкой 🗑 или очищай весь список через **🧹 Удалить всех пользователей** с подтверждением.
- **Шаблоны сообщений** → создавай сколько угодно заготовок: после названия отправь боту один или несколько готовых постов, включая HTML/Telegram-разметку, premium emoji, фото/альбомы из фото и inline-кнопки. При сборке шаблона можно добавить URL-кнопку к последнему посту вручную (`Текст кнопки | https://example.com`) и задать задержку между постами, например `10` секунд: первый пост уйдёт сразу, следующий — через 10 секунд. Если у управляющего бота включён inline mode, userbot отправит текстовые посты и посты с одним фото как `via @bot` с настоящей кнопкой под сообщением. Затем нажми **«Это всё, сохранить»**. Бот сохранит шаблон и пришлёт предпросмотр.
- **Разовая рассылка** → выбираешь один шаблон или **🔀 Ротацию всех шаблонов**, выбираешь группу получателей (или «Все»), затем выбираешь один или несколько авторизованных аккаунтов отправки. После этого можно включить фильтр по чату: укажи @username, ссылку или id чата/канала/группы, и если получатель уже состоит там, бот пропустит его и запишет в логи как `skipped`. Для такой проверки каждый выбранный юзербот-аккаунт должен сам состоять в этом чате и иметь возможность видеть участников. Если выбрано несколько аккаунтов, получатели распределяются между ними и отправка идёт параллельно. Во время отправки бот показывает live-скоринг доставки: прогресс, успешные отправки, пропуски, ошибки, процент успешности и аккаунт последней попытки. Кнопки **⏸ Пауза / ▶️ Продолжить** позволяют приостановить всю активную рассылку или конкретный аккаунт без потери очереди. После завершения появляется кнопка **📋 Результаты этой рассылки**: отдельно видно, кому отправлено и кому не отправлено с причиной; полный отчёт можно скачать в CSV.
- **Расписание** → один шаблон или **🔀 Ротация всех шаблонов** + группа + время (ЧЧ:ММ) + дни недели (`mon,tue,wed` или `*` для каждого дня). Планировщик проверяет расписания каждые 30 секунд и запускает рассылку в нужное время.
- **Логи** → последние 20 отправок с результатом (успех/ошибка).
- **Настройки** → изменить интервал случайной задержки между сообщениями (например `2-5`, т.е. от 2 до 5 сек) прямо из бота, без правки `config.py` и без перезапуска — значение сохраняется в базе и применяется сразу к следующей рассылке.
- **Админ-панель** → доступна только root-админам из `ADMIN_IDS`: выдача доступа по `@username`, список пользователей, включение/отключение доступа.

## Важные технические ограничения

- Отправка идёт от **реального личного аккаунта**, а не через официальный Bot API. Такой режим работы (userbot / автоматизация обычного аккаунта) не входит в официально поддерживаемые Telegram сценарии использования — при слишком агрессивной рассылке (много сообщений подряд новым людям) Telegram может временно ограничить аккаунт (flood-wait) вплоть до блокировки при систематических жалобах. В коде уже заложена **случайная задержка** между сообщениями — перед каждой отправкой берётся случайное число секунд из интервала `[MIN; MAX]`, чтобы интервалы не выглядели подозрительно ровными. По умолчанию это 2.0–4.5 сек (`SEND_DELAY_MIN_SECONDS` / `SEND_DELAY_MAX_SECONDS` в `config.py`) — не уменьшай сильно.
- Inline-кнопки сохраняются и отображаются в предпросмотре. При отправке через личный аккаунт настоящая кнопка под постом возможна через inline mode бота: сообщение уйдёт с меткой `via @bot`. Если inline mode выключен, Telegram не вернул inline-результат, пост является альбомом или у старого фото нет `file_id`, URL-кнопки добавляются в сообщение как кликабельные ссылки.
- Задержка в шаблоне применяется внутри одного шаблона между его постами. Глобальная случайная задержка из **Настроек** по-прежнему применяется между разными получателями рассылки.
- Ротация шаблонов полезна для внутренних уведомлений, когда есть несколько равноценных формулировок одного сообщения. Она не отменяет лимиты Telegram и не защищает от жалоб: отправляй сообщения только тем, кто ожидает такие уведомления.
- Пользователям, у которых в настройках приватности запрещено писать первым тем, кто не в контактах, сообщение не дойдёт — в логах это будет видно как ошибка.
- Рекомендуется заранее добавить юзербот-аккаунт в контакты пользователей (или наоборот) — это снижает риск ограничений.
- Процесс должен работать постоянно (например, на сервере через `systemd`, `screen`/`tmux` или Docker), чтобы расписания срабатывали вовремя.

## Запуск в фоне на сервере (пример через systemd)

Создай `/etc/systemd/system/tg-broadcast.service`:

```ini
[Unit]
Description=Telegram Broadcast Userbot
After=network.target

[Service]
WorkingDirectory=/path/to/tg_broadcast_tool
ExecStart=/path/to/tg_broadcast_tool/venv/bin/python main.py
Restart=always
User=youruser

[Install]
WantedBy=multi-user.target
```

Затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tg-broadcast
```

## Общий реестр отправок и автопарсер по ключевым словам

В этой версии добавлен единый реестр `delivery_registry`. Для одного владельца панели
получатель считается обработанным независимо от того, с какого из его аккаунтов была
выполнена отправка. Перед отправкой используется атомарное резервирование, поэтому два
аккаунта, работающие параллельно, не отправят одному получателю дубликат.

Старые успешные записи из `logs` автоматически переносятся в реестр при запуске.
В главном меню появился раздел **«📚 Реестр отправок»**. Проверка конкретного пользователя:

- `/sent_check @username`
- `/sent_check 123456789`
- `/sent_registry` — последние записи реестра.

### Наблюдение за чатами

В главном меню появился раздел **«🔎 Автопарсер»**.

Добавление правила:

`/watch_add ACCOUNT_ID CHAT TEMPLATE_ID ключ1,ключ2`

Пример:

`/watch_add 2 @mychat 5 ремонт,смета,дизайн`

Дополнительные команды:

- `/watch_list` — показать правила;
- `/watch_del ID` — удалить правило.

Совпадения сохраняются в `keyword_hits` вместе с названием чата, id сообщения,
пользователем и найденным ключевым словом. Автоматическое личное сообщение отправляется
только если пользователь ранее сам писал выбранному аккаунту в личном диалоге. Если
предыдущего входящего ЛС не было, совпадение фиксируется как кандидат без автоматической
отправки. Это предотвращает холодные автоматические DM.

## Кнопочный автопарсер и общий реестр

В главном меню доступны разделы **«🔎 Автопарсер»** и **«📚 Реестр отправок»**.

Автопарсер настраивается кнопками: выбрать аккаунт → указать чат → выбрать шаблон → ввести ключевые слова. В разделе правил можно удалять наблюдаемые чаты, а в журнале совпадений — проверять найденного пользователя по общему реестру одной кнопкой.

Общий реестр учитывает отправки со всех аккаунтов текущего владельца и показывает аккаунт, источник/чат, статус и время. Автоматический ответ по ключевым словам выполняется только для пользователя, который ранее уже сам писал выбранному аккаунту в личные сообщения; остальные совпадения сохраняются в журнал без автоматического DM.


## Пауза и отчёты по рассылке

- Полная остановка из обычного интерфейса заменена на **паузу**. Очередь сохраняется, а после **«Продолжить»** обработка продолжается с того же места.
- При ошибках `PeerFlood`/`FloodWait` текущая рассылка автоматически ставится на паузу. Код не переключается на другой аккаунт для обхода ограничения Telegram. Продолжать следует только после того, как ограничение действительно снято.
- Каждый запуск записывается отдельно в `broadcast_runs`, а результат каждого получателя — в `broadcast_run_items`. После завершения доступна кнопка **«📋 Результаты этой рассылки»** с разделами **«✅ Отправлено»**, **«❌ Не отправлено»** и выгрузкой полного CSV.

## Состояние аккаунтов и техническое автопереключение

В разделе **«🔐 Авторизация юзербота»** доступны:

- **🩺 Проверить аккаунты** — без тестовой рассылки проверяет доступность сессии, авторизацию и возможность получить профиль аккаунта.
- **🔁 Автопереключение при тех. сбоях: ВКЛ/ВЫКЛ** — настройка сохраняется отдельно для каждого владельца панели.
- Статусы аккаунтов: **✅ работает**, **🔐 не авторизован**, **⚠️ техническая ошибка**, **🚫 ограничение отправки**, **◻️ не проверен**.

Если автопереключение включено и выбранный аккаунт становится технически недоступен
(например, сессия отозвана, соединение оборвалось или произошла серверная/сетевая ошибка),
его оставшаяся очередь переносится на другой **уже выбранный** и исправный аккаунт. Сам
неисправный аккаунт исключается до конца текущего запуска, а факт переназначения виден
в live-статусе и итоговом отчёте.

`PeerFlood`, `FloodWait` и другие ограничения на исходящие сообщения не используются как
триггер для автопереключения: при них рассылка ставится на **паузу**. Если технический
сбой произошёл после отправки части много-постового шаблона, автоматический повтор тоже
не выполняется, чтобы не создать дубликаты; запуск ставится на паузу и причина попадает
в отчёт.

## Checkpoint рассылки и ограничения отправки

- Перед стартом рассылки создаётся persistent-очередь `broadcast_run_items` со стабильной позицией каждого получателя.
- После успешной отправки/пропуска/ошибки статус элемента обновляется в SQLite. Необработанные элементы остаются `pending`.
- При ограничении отправки (`PeerFlood`/похожее ограничение) текущий получатель возвращается в `pending`, весь запуск получает статус `paused`, сохраняется аккаунт и причина паузы.
- В live-экране и отчёте появляется кнопка **🔄 Проверить и продолжить**. Она запрашивает статус у официального `@SpamBot`; если ограничение ещё действует, рассылка остаётся на паузе и показывается срок. Если ограничение больше не обнаружено, сохранённая очередь продолжается с текущего места.
- Если бот был перезапущен, элементы со статусом `sending` возвращаются в `pending`, после чего очередь можно восстановить из SQLite.
- Кнопка **👥 Оставшиеся** показывает необработанных пользователей и выдаёт CSV `broadcast_<id>_remaining.csv`.
- В разделе рассылок есть **📂 Последние рассылки**, откуда можно открыть отчёт и незавершённый запуск.
- Автопереключение аккаунтов применяется только к техническим сбоям сессии/соединения; при активном ограничении отправки оно не используется.

## Массовое добавление автопарсера и скан истории

В разделе **«🔎 Автопарсер»** теперь можно вставлять несколько чатов одним сообщением —
по одному на строку либо через запятую/точку с запятой. Поддерживаются `@username`,
`t.me`-ссылки и числовые ID. Ключевые слова и фразы вводятся таким же списком. Перед
созданием правил бот показывает предпросмотр: сколько чатов распознано, сколько ключей
получено и какие чаты не удалось открыть выбранным аккаунтом. Дубли во входном списке
удаляются, а полностью совпадающие существующие правила повторно не создаются.

Кнопка **«📚 Просканировать историю»** позволяет выбрать одно правило или все активные и
просмотреть последние 100/500/1000 сообщений либо сообщения за 1/3/7 дней. Для скана по
периоду действует технический предел 10 000 сообщений на чат. Исторический скан **никому
не отправляет сообщения**: он только записывает найденные совпадения в `keyword_hits`.
Повторный скан той же истории не дублирует уже сохранённые записи благодаря уникальному
ключу сообщения. Live-парсер продолжает работать только с новыми сообщениями после
подключения listener-а.

### Недействительные invite-ссылки
Если при массовом добавлении правил, импорте участников или сканировании истории встречается
просроченная/недействительная приватная invite-ссылка, бот не должен завершать операцию с
`CheckChatInviteRequest`. Такая ссылка помечается как недоступная, а остальные чаты продолжают
обрабатываться. Для уже сохранённого правила сначала используется сохранённый `chat_id` и список
диалогов аккаунта, поэтому истёкшая старая ссылка не мешает работе, если аккаунт всё ещё состоит
в этом чате.

### Приватные чаты с истёкшей invite-ссылкой

Telegram не позволяет восстановить `chat_id` из уже просроченного invite hash. Поэтому в разделе
автопарсера после выбора аккаунта есть кнопка **«📋 Выбрать из доступных чатов»**. Она показывает
группы и каналы, которые уже доступны выбранному аккаунту. Можно отметить несколько чатов и добавить
их без повторного использования invite-ссылки. Для публичных чатов по-прежнему можно вводить
`@username`, `t.me`-ссылки и числовые `chat_id` списком.
